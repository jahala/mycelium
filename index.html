why

One agent can't ask another.

Agent sessions run side by side on one machine, each with its own context, and none of them can put a question to the next. A supervisor can carry messages down to its workers, but then every answer waits on the supervisor. mycelium gives each agent a mailbox. One asks, the other's watcher rings, it answers, and the asker reads the reply and carries on. It works in any MCP host, such as Claude Code, Codex CLI and Gemini CLI, and the agent never knows whether a message came through a file or across machines.

what it refuses

  • a stranger, until a person lets it in
  • ringing out a message you denied
  • a knock that overwrites the one before
  • an unread message lost to a restart
  • two servers on one id
  • a dependency

the gate

Strangers knock; you decide.

Messages between programs are safe only when a person decides who is let in. A peer nobody has vouched for is held at the gate, and the sender is told so: Held at web's trust gate. A held knock survives a restart, because the gate is read back from the journal.

what a knock becomes

  • heldkept out of the inbox; the watcher rings without quoting it
  • delivereda person allows the peer, and every knock it made arrives, oldest first
  • deniedthe message is dropped and never rung out

A peer you allow stays allowed after a restart.

the tools

Six tools in the agent's hands

  1. 1

    mycelium_send

    sends a message to a peer, and says what became of it: sent, held at the gate, or queued until the peer starts.

  2. 2

    mycelium_inbox

    hands over what has arrived, each line with its sender, time and place in the journal, then names anyone held at the gate.

  3. 3

    mycelium_agents

    lists the peers you can reach, whether each is running, and whether they have read what you sent.

  4. 4

    mycelium_allow

    lets a peer in, now and after a restart, and delivers everything it had waiting at the gate.

  5. 5

    mycelium_deny

    drops a held peer's messages without repeating them.

  6. 6

    mycelium_rename

    takes the id a director expects. Unread mail, knocks and allowed peers come along.

one file, three modes

Raw MCP over stdio, with no SDK. On one machine the mailboxes are files; across machines an HTTP relay carries them.

  • node mycelium.mjsthe MCP server your host spawns.
  • node mycelium.mjs --watch <id>the doorbell: one line per arrival, so a harness that reads lines can wake the agent.
  • node mycelium.mjs --relayan HTTP hop between machines, over any tunnel or VPN.

Every arrival is written to an append-only journal before the mailbox file is removed, and a cursor records how far the agent has read. A message that arrived but was never read is still there after a restart, and the agent is told how many are waiting.

Install

Node 18 or newer, nothing else. Tell your agent Install mycelium from https://github.com/jahala/mycelium, or fetch the one file and add it to .mcp.json:

curl -O https://raw.githubusercontent.com/jahala/mycelium/main/mycelium.mjs
# then, in .mcp.json
{
  "mcpServers": {
    "mycelium": {
      "command": "node",
      "args": ["./mycelium.mjs"]
    }
  }
}

Then wake the agent with node mycelium.mjs --watch <id>

Run the watcher in a tool that reads lines as they come, such as Claude Code's Monitor. The id is the name of the directory the agent starts in, so every project and worktree gets its own mailbox. These settings go in the server's env:

  • MYCELIUM_IDthe agent's id, in place of the directory name
  • MYCELIUM_ALLOWpeers let in without a knock, comma-separated, or * for anyone
  • MYCELIUM_RELAYthe relay's URL, to reach agents on other machines
  • MYCELIUM_DIRthe mailbox root, /tmp/mycelium by default
  • MYCELIUM_PORTthe relay's port, 4747 by default

Across machines, start node mycelium.mjs --relay on one, expose it with any tunnel (cloudflared tunnel --url http://localhost:4747 needs no account), and give the others its URL. The rest is in the README.
